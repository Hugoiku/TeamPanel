# agents/ · 员工提示词

每个员工由两段拼成，**顺序固定**：

    system prompt = agents/_COMMON.md  +  agents/<role>/ROLE.md  +  mission（本 case 的目标与启用角色）

| 文件 | 作用 | 什么时候改 |
|---|---|---|
| `_COMMON.md` | 通用协议：唯一写入口、锁与排队、门禁、能力边界、上下文丢失、禁止事项 | 改协议才动它，六个角色共享 |
| `<role>/ROLE.md` | 角色卡：职责、输入、输出模板、DoD、禁止事项 | 改职责才动它 |
| `_ROLE.template.md` | 写新角色时的骨架 | 参考用 |

## 为什么分两层

协议是**约束**，角色是**职责**。混在一起会出现两个问题：
1. 六个文件里重复六份协议，改一处要改六处，必然漂移；
2. 员工把"协议"当成"建议"——因为它在角色卡中间，看起来像角色描述的一部分。

分开之后，`_COMMON.md` 是**规则**（违反就是违规，会被 Broker 的巡检抓住），`ROLE.md` 是**岗位说明书**。

## 角色清单

| id | 角色 | 一句话职责 | 主要产出 |
|---|---|---|---|
| `macro` | 宏观研究员 | 政策/流动性/汇率/财政的方向与拐点 | `research/macro.md` |
| `industry` | 行业研究员 | 供需、竞争、渠道库存、景气度 | `research/industry.md` |
| `stock` | 个股研究员 | 护城河、财务质量、估值 | `research/stock.md` |
| `audit` | 信息审计 | 只核验不创作：来源覆盖率 + 抽样偏差 | `review/audit.md` |
| `legal` | 法律顾问 | 合规边界：内幕信息、绝对化表述、免责 | `review/legal.md` |
| `trader` | 交易员 | 把结论翻成仓位/入场/止损 | `trade/plan.md` |

## 分离原则（这套提示词最重要的设计）

- **审计不创作**：`audit` 不能补来源、不能改结论，只能出意见；
- **法务不判断价值**：`legal` 只判合规，不做投资判断；
- **交易员不做研究**：`trader` 只用已通过审计的结论，不调整评级；
- **宏观不碰估值**，**行业不给目标价**，**个股不碰宏观判断**。

每条都对应一个"越界即违规"的检查点。

## 怎么用

- 面板里选中员工 → 会话头「提示词」按钮 → 直接看到这两段（角色卡 / 通用协议切换）；
- 由 Lead 派活时，把 `_COMMON.md` + `ROLE.md` 作为 teammate 的 system prompt 装载；
- 版本：两段都算 prompt 版本，写进 `mission.created.payload.prompt_versions`，回放时才能还原"当时用的是哪版规则"。
