# M6：缺什么就问 —— 员工的“主动提问”与会话面板对齐 DSH

## 1. 原则

分析过程中缺数据、缺来源、缺技能、缺插件、缺权限、缺口径时，员工**不许编造、不许拿「待补」糊过去**，
必须把缺口变成一条可答复的请求写进账本，由监督者在面板上回答；答复在员工下一轮启动时注入提示词。

## 2. 数据模型（Broker）

| 事件 | 含义 |
|---|---|
| `need.requested` | 员工提出缺口：kind = data / skill / info / plugin / permission / other，blocking 标记是否阻塞交付 |
| `need.answered` | 监督者答复（或批准/拒绝权限申请） |
| `need.partial` | 部分答复：只保存说明，缺口仍缺数据 |
| `need.waived` | 缺口豁免：明确不补，解除阻塞 |
| `need.auto` | 数据项自动采集状态变化（queued/running/done/failed/no_source/needs_review） |
| `data.job.fallback` | 数据任务按免费优先链换源（from/to/attempts），重启可回放 |
| `data.job.evidence` | 自动采集写 S# 证据（evidenceId/sha256/dataAsOf/qualityOk） |
| `data.credentials.updated` | 数据源凭据保存/探测（provider/configured/available/reason，无明文） |
| `source.health.refresh` | 数据源定时体检触发（每 6h，后台 source-doctor） |
| `report.sign.stale_accepted` | 签发时人工接受过期数据（reason + 过期项） |
| `need.items.provided` | 逐项补齐结果，重启后 item.status/value/source 不丢 |
| `need.source.added` | 来源包添加 URL/文件来源 |
| `need.parse.started` / `need.parse.finished` | 来源解析开始/结束（含失败原因） |
| `need.candidate.created` | 解析生成候选值，不自动入库 |
| `need.candidate.decided` | 人工接受/拒绝候选 |
| `need.conflict.opened` / `need.conflict.resolved` | 多来源冲突打开/裁决或豁免 |
| `need.item.waived` | 单指标显式豁免 |
| `report.stale` | 数据补充后已有最终报告失效 |
| `file.uploaded` | 监督者上传附件到 `vault/uploads/`，进版本与历史，不算员工写入 |

接口：`POST /api/need`、`GET /api/needs`、`POST /api/need/answer`、`POST /api/need/waive`、`POST /api/need/item/provide`、`POST /api/need/preview-url`、`POST /api/need/commit-url`、`POST /api/upload`；数据源状态/配置：`GET /api/data/source-health`、`POST /api/data/source-health/refresh`、`GET/POST /api/data/credentials`、`POST /api/data/source/register`、`GET /api/data/preflight`；报告：`GET /api/report/freshness`；重启后由账本重放。

`GET /api/needs` 每个缺口额外返回 `queue`（auto/human/closed）、`stage`、`reason`，面板据此拆分“自动采集中”和“待补数据”。

## 3. 员工侧

```bash
# 缺东西：一句话说清缺什么 + 要它干什么
./scripts/desk need --kind data --title "缺近 8 季营收与净利润" --detail "用来做估值锚，缺它 target_range 只能为 null"

# 看自己提过的问题与答复
./scripts/desk need --list
```

`runtime/agents/employee.js` 启动时会把「你已经拿到的答复」拼进提示词，所以答复不需要人工转述。

## 4. 面板（对齐 DSH 对话框）

- 左栏新增 **待你确认**：每条缺口显示「类型 · 员工 · BLOCK」，权限类给「批准 / 拒绝」，其余给输入框 + 答复；
- 待补队列只放 `queue=human` 的缺口；`auto` 只在待办区显示“自动采集中”，不混入人工补数；
- 缺口弹窗显示当前 `stage` 与 `reason`（自动采集中 / 重试耗尽 / 无数据源 / 来源待启用 / 数据质量待确认 / 需人工补充）；`no_source` 的 reason 会列出每个来源缺什么（token/积分/账号），并提示上传 CSV 或配置免费 Key；
- 右栏「数据源」手风琴：免费可用 / 需配置 / 可选积分三组，显示层级、原因、申请地址，可一键重新检测；
- 数据类缺口提供 **来源包**：多 URL 解析候选 → 人工勾选 → 确认入库；候选不自动入库；
- 输入框旁 **＋附件**：上传后落到 `vault/uploads/<时间戳>-<文件名>`，写 `file.uploaded`，员工用 `desk cat` 读；
- 账本流水显示 `研究员 提出「缺数据」…`、`你 答复 …`、`你 上传 …`。

## 6. 还没做（继续对齐 DSH 对话框）

1. 附件解析：PDF/Excel 抽取成文本与表格，生成 `[S#]` 证据条目（现在只是原样落盘）；
2. 引用：输入框 @文件 / @员工，消息带上文件版本；
3. 权限粒度：目录级、时效、只读范围（现在 permission 只有批准/拒绝）；
4. 多轮上下文：面板里的对话历史与员工会话上下文的合并展示；
5. 技能缺口与技能安装联动：`kind=skill` 的答复可以直接触发安装 + 装配（目前只记录答复）。

## 7. 交付物预览与下载（对齐 DSH 的文件卡片）

- 交付物列表和右栏「共享文件」的每一行都可点击 → 弹窗预览；
- 预览按扩展名分流：`.md` 走自写的迷你 markdown 渲染（标题/列表/表格/加粗/行内代码/分割线）、
  `.json` 格式化、图片 `inline` 打开、PDF 提示下载、其它按文本 `pre` 展示；
- 弹窗底部：`vN · sha 前 12 位 · 路径`，右侧「复制路径 / 下载 / 关闭」；
- 下载走新接口 `GET /api/download?case=<case>&path=<rel>`，带 `Content-Disposition: attachment`；
  预览用 `file` 接口拿内容，图片/PDF 用 `download?inline=1`；
- 深链：`/live?case=xxx&file=research/macro.md` 直接打开某个文件的预览（方便分享定位）。

## 8. 一轮即止：跑完就交付给用户，不自动进下一轮

- 一轮 = 6 个角色各跑一次 + Lead 汇编终稿；跑完由 pipeline 调 `POST /api/cycle/finish` 把这一轮标成 `awaiting_review`；
- 面板顶部出现绿色横幅：「本轮已完成 · 文件 N 个 · 门禁 M 条 · 已停下等你查看（不会自动进入下一轮）」，按钮：
  查看终稿 / 看门禁结论 / 开始下一轮（需你点确认）；
- 循环保护：
  1. `POST /api/cycle/start` 在这一轮仍是 `running` 或 `awaiting_review` 时返回 409，不会自己开新轮；
  2. `scripts/pipeline.js` 启动时检查 cycle 状态，`awaiting_review` 且没有 `--force` 直接退出（退出码 4）；
  3. 没有定时器/自动重排在跑 pipeline——下一轮只能来自人的显式动作（面板按钮或命令行）。

## 9. 复核服务状态机（audit / legal）

一次复核 = (产物路径, 版本, audit|legal)，状态：requested → clean | conditional | returned；产物升版 → 旧结论 stale；监督者可 waived。

- 接口：POST /api/review/request（幂等：同产物同版本不重复建）、POST /api/review/verdict、POST /api/review/waive、GET /api/reviews（含 counts 与 stale 结算）、GET /api/cycle/readiness；
- 命令行：desk review --list | --request --service audit --path X --criteria "..." | --verdict --id R1 --result pass|conditional|fail --finding "..." | --waive --id R1；
- 结算规则集中在 Broker 的 readinessOf()：pending_review / stale_review / returned / conditional / pending need 都算 blocker；cycle.finish 只有 blockers 为空才置 awaiting_review，否则置 blocked 并列出 blockers；
- pipeline 改成请求驱动：研究产物落地后自动发复核请求（宏观/行业/个股 → 审计，个股 → 法务），评审阶段由审计/法务按队列出结论，交易前做 readiness 收敛检查（未收敛就停在交易前并登记 cycle.failed），交易计划落地后再发一次法务复核（交易后合规）；
- 面板：左栏新增「复核队列」，显示 服务 / 产物 vN / 轮次 / 修订项数 / 状态，退回、带条件、已过期的条目可由监督者一键「豁免」。
