# M8：报告标准与 G-REPORT 签发前检查

## 报告标准（正式研究报告结构）

摘要 / 一、宏观环境 / 二、行业格局 / 三、公司分析 / 四、财务与估值 / 五、市场表现与图表 /
六、审计与合规意见 / 七、交易计划 / 八、风险与待验证 / 附录 A 证据池 / 附录 B 数据说明 / 免责声明。

- 每章必须是“结论 + 论据 + 数据/引用”，不是目录式摘要；
- 正文引用 `[S#]` 必须能在 `evidence/sources.jsonl` 找到；
- 图表必须是真实接口数据生成（`scripts/report.js` 从 Tushare/东财重取），不能用示意图；
- 交易章节在没有交易计划时如实写“未生成”，不编仓位；
- 汇编层不新增数字。

## G-REPORT 检查（scripts/check-report.js）

| 检查 | 规则 |
|---|---|
| file | 终稿存在且 v>0 |
| sections | 10 个关键章节齐全（摘要/宏观/行业/公司/估值/审计/交易计划/风险/附录/免责声明） |
| chars | 正文 ≥ 6000 字符 |
| refs | `[S#]` 引用 ≥ 50 处 |
| evidence | 证据池非空 |
| dangling | 引用的每个 [S#] 都能在证据池找到 |
| figures | 图片 ≥ 2 张且文件存在 |
| disclaimer | 含“不构成投资建议” |
| readiness | `GET /api/cycle/readiness` 为 ready（复核收敛、无待答复 need） |

退出码：0 全过，3 有未通过项；`--write` 时把结果写成 `G-REPORT::final_report.md` 门禁（pass/fail）+ note。

## 签发集成

- `POST /api/sign` 先异步跑 check-report，未通过返回 **409** + `checks[]`，不签发；
- 面板“签发报告”会把失败项以 toast 列出（`签发被拦：3 项未通过 · readiness / …`）；
- 确实要带问题签发需显式 `force:true`（应记 waive，后续补）。

## 踩坑记录

check-report 会回调 Broker（desk cat / gate），**不能在 Broker 里用 spawnSync**——单线程会死锁：
Broker 阻塞等子进程，子进程等 Broker 响应。改为 `spawn` + Promise 等 close 才正常。

### 自动汇编（pipeline 已接入）

- 每轮跑完（所有阶段结束后）pipeline 会自动调用 `report.js` 生成带图终稿，再跑 `check-report.js --write` 报 G-REPORT；
- 手动重出报告：`node scripts/pipeline.js --case <case> --report-only`；
- 跳过自动汇编：`node scripts/pipeline.js --case <case> --no-report`；
- 报告结构按市场常见个股深度报告：投资要点 → 基本数据 → 公司概况与商业模式 → 行业分析 → 宏观与产业链传导 → 经营与财务分析 → 盈利预测与估值 → 催化剂与风险 → 投资建议 → 待验证 → 附录 A 证据池 / B 图表口径 / C 评级说明与免责声明。
