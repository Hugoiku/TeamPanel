## 3. 数据映射

| 面板元素 | 真实来源 |
|---|---|
| 中栏账本流水 | /api/events 增量（since=seq） |
| 泳道图节点 | file.written / gate.* / lock.queued / lock.timeout / file.conflict / lock.expired |
| 血缘边 | 同车道上一个图节点（补上了 Broker 不提供的 parents） |
| 锁队列 | /api/snapshot 的 files[].holders / queue |
| 门禁 | /api/snapshot 的 gates |
| 左栏员工状态 | 持锁=工作中 / 排队=等待 / 有写过=已交付 |

## 4. 这轮修掉的三个问题

1. **租约倒计时显示 1.7 亿秒** —— broker 给的是毫秒剩余，面板用的是相对秒，单位没换算。
2. **泳道节点出现「审计 v0」** —— 面板复用了 sim 的短标签逻辑（把 gate.failed 当成审计提交），live 节点必须自带 short。
3. **节点重叠** —— 同一车道 3 个节点挤在 6 秒内，两行都占满时直接叠在一起；改成占满后右移重试。

## 5. 已知边界

- live 模式**只读**：派活、审批、模型切换仍是 M3 的事（需要 broker 暴露对应接口）。
- 员工「会话」在 live 下退化为账本流水（没有 thread 概念，因为 broker 还没有消息接口）。
- 泳道图血缘是面板推的，不是 broker 给的 —— M3 应把 parents 写进事件。
