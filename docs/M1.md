## 5. 已知取舍

1. **排队超时会踢出队列。** 客户端等 wait_ms（默认 30s）拿不到锁就返回 202 并让位，避免"呼叫方死了但队列里挂着幽灵"。代价是极端情况下 FIFO 会重排——6 人团队下可接受，人多要改成"保留队列位置 + 心跳"。
2. **重启后队列清空。** 账本能重放文件版本和门禁，但没法重放"谁在排队"（进程已死）。重启会发 broker.started，Agent 需要重试——这正是 TTL + 重试该有的行为。
3. **写成功自动释放锁。** 与设计一致（写 = 一次事务），不走显式 release。
4. **没有鉴权。** 监听 127.0.0.1，M1 假设同机可信。多人协作要加 token。
