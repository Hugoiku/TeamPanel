# Panel UI 设计参考：Lancer（raylee-ai/lancer）

> 研究对象：https://github.com/raylee-ai/lancer（桌面 AI 工作区，右侧 GitTree / multi-lane graph）与 `packages/light-ui`（从桌面端抽出的光线 UI）。本文件记录从它提取的设计架构，以及 AlphaDesk 面板实际采纳的部分。

## 1. 提取到的 UI 架构

### 1.1 Design tokens（`apps/desktop/src/styles/tokens.css`）

| 类别 | 规则 |
|---|---|
| 间距 | 4px 基准（2/4/6/8/10/12/16/20/24/28/32） |
| 字号 | 紧凑档 11 / 12 / 14 / 16 / 20 / 28px，字重 400/500/600/700 |
| 圆角 | 2/4/6/8/10/12/14/16/18px + pill（999）与 50% |
| 边框 | 前景色 alpha mix（5%/8%/13%），自动适配明暗主题，不用硬编码灰 |
| 阴影 | 「hairline stroke + 小阴影」组合（Codex 风格），不用大面积模糊 |
| 动效 | 0.12/0.15/0.24s，`cubic-bezier(0,0,.2,1)`；受限动效时直接完成 |
| 语义色 | 绿=运行中、红=失败、琥珀=需注意、灰=空闲、accent=选中/未读 |

### 1.2 右侧工作树 / 多泳道（`styles/session-trajectory.css`）

- **多泳道 = 列**：`--lane-columns` 列网格，每列一个会话/角色；列头 = 色点 + 名称 + 状态，活动列加下划线（`inset 0 -2px 0 lane-color`）。
- **节点 = 列表卡片**：`glyph + title + preview` 两行；hover 高亮（lane-color 10% 底）；分支节点按 `--graph-column` 缩进；跨列交接用 SVG 覆盖层画虚线（`stroke-dasharray: 4 3` + `lancer-handoff-draw` 0.8s 画出）。
- **聚焦**：只展示当前会话并居中；「全部」显示所有根会话。
- **图例**：底部小 chip，说明节点/交接/交付。
- 长历史纵向滚动、超宽横向滚动；节点进入有 0.3s ease 入场。

### 1.3 光线层（`packages/light-ui`）

- 事件驱动：`createLightLayer().emit({id, source, target, color})`，从模型/气泡飞到工作树节点；`flight.finished = arrived | cancelled | missing-anchor`。
- 每次发射固定轨迹、慢起-中段快-慢落（默认 1.2s）；同一次飞行不抖动；最多 128 条并发生命周期；空闲不跑帧循环；`prefers-reduced-motion` 直接完成。
- 正在运行的节点有细窄同色**流动边框**，完成后移除；业务状态必须有文字提示，动效只作补充。
- 语义 ID 连接（会话/事件/父节点），禁止按最近坐标猜关系。

## 2. AlphaDesk 面板采纳了什么

| Lancer 设计 | 本项目落地 |
|---|---|
| 泳道=列（不是甘特行） | 右侧「泳道提交图」改为 5 列：宏观/行业/个股/交易/Lead；列头色点+名称+状态+交付数 |
| 节点=卡片（glyph+title+preview） | 卡片=交付物：类型色点 + 名称 + `时间 · 负责人 · 共N版`，点击直接预览文件 |
| 跨列交接虚线动画 | 父→子事件用 lane 色虚线（`gflow` 1.1s 流动），链接用紫色虚线（产物被下游读取） |
| 聚焦当前会话 | 顶部 chip「全部/宏观/行业/…」点击聚焦，其余列淡化；再点取消 |
| 长历史滚动、超宽滚动 | 列内纵向滚动；⌘/Ctrl+滚轮缩放，工具栏「适应」复位 |
| hover 高亮 | hover 节点时只亮它的上下游血缘（节点+边），其余淡化 |
| 版本收敛（业务侧） | 同一路径只显示最新版（复核中的版本保留），避免 v1..v8 刷屏；卡片标「共N版」 |
| 语义色 | 绿=运行中、琥珀=等待、红=被阻塞/退回、紫=读取链接、灰=空闲 |
| 空车道提示 | 交易列无产出时显示「暂无交付物 · 等待上游或派活」 |

### 未采纳 / 后续可做

- **光线飞行**：需要真实 DOM 锚点（气泡/模型图标 ↔ 节点），当前中栏是文本流水，落地价值有限；若后续做气泡化会话可接 `light-layer` 的 SVG 轨迹（同色、1.2s、reduced-motion）。
- **多会话并行**：本项目是单 case 多角色，不存在多根会话；列=角色已覆盖。
- **节点入场动画 / 代码高亮**：低优先，先保信息密度与稳定性。

## 3. 实现位置

- `dashboard/template.html`：`renderGraph()`（多列渲染）、`.g*` 样式（工具条/图例/缩放/高亮）、点击/滚轮/hover 事件绑定；
- 账本仍为唯一数据源：列、卡片、边都由 `S.events / S.reviews / S.links` 投影，不新增状态；
- 面板测试 `dashboard/test.js`（202 项）保持全通过。


### 工作流模式（2026-10 追加，默认）

Lancer 的 GitTree 展示的是**每个会话的完整工作轨迹**（消息、步骤、工具调用、分支/合并、交付节点），不是只列交付物。AlphaDesk 面板现在对齐这个语义：

- 顶部「工作流 / 交付物」切换，**默认工作流**；
- 工作流列 = 7 个员工（宏观/行业/个股/审计/法律/交易/Lead），每列按时间从上到下排该员工的记录：派活、启动会话、本轮结束、缺数据/答复、门禁、复核请求/结论、存库、上传、交付物、轮次状态；
- 交付物卡片实线加粗（可点开文件），过程事件用细虚线卡片；同路径历史版本折叠为最新一版并标「共N版」，每列最多显示最近 18 条（更早折叠提示）；
- 交付物模式仍保留：只看每人的交付结果，适合验收/汇报；
- 两种模式共用：泳道聚焦、⌘/Ctrl+滚轮缩放、适应、hover 血缘高亮、点节点预览文件。

### 审计/法律：循环服务，不单独成列（2026-10 修正）

- 泳道主列只保留**主环节**：宏观 / 行业 / 个股 / 交易 / Lead；
- 信息审计、法律顾问是**主环节触发的循环服务**，它们的 `review.requested` / `review.verdict` 会按被复核产物的路径挂回主列：
  - `research/macro.md` → 宏观列；`research/industry.md` → 行业列；`research/stock.md` → 个股列；`trade/plan.md` → 交易列；`final_report.md` → Lead 列；
  - 服务卡片用服务色（审计=琥珀、法务=玫红）描边，虚线连到被复核的交付物/复核请求；
  - 列里同时看得到「谁在什么时候触发复核、结论是什么」，不需要单独两列，泳道更紧凑。
- 交付物模式仍然只画交付物，服务结论不再单独列（审计/法务结论仍在卡片旁的状态里体现）。

### 光线与视图状态（2026-10 追加）

- 每条泳道最新一条记录：列头有细光线落到卡片（`glight` 虚线流动），卡片描边有 `gnew` 呼吸动画；新事件到达时自动前移；
- 视图状态写入 URL：`?mode=deliverables&focus=stock&zoom=1.2`，刷新/分享可复现同一视图；
- 默认 `mode=workflow`、`focus=all`、`zoom=auto`（按容器宽度自适应）。

### 过程折叠（2026-10 追加）

- 工作流列里，连续 ≥3 条「缺口/门禁/存库/上传/轮次」这类过程事件折叠成一张「过程 N 步（门禁/缺口/存库…）· 点开展开」卡片；
- 交付物、派活、启动/结束、复核步骤不折叠，保证关键节点始终可见；
- 交付物模式里，审计/法务结论以服务步骤 chip 挂在对应版本产物卡片下方（虚线连接），不再单独列。

### 光线飞行（真正的 DOM 锚点）

- 新事件到达时：中栏账本流水行（`data-seq`）→ 泳道卡片（`data-seq`）画一条同色贝塞尔光路 + 移动光点，约 0.9s 到达、1.5s 后清理；
- 找不到目标卡片（如 `file.accessed`/锁事件不在泳道图里）就不飞；`prefers-reduced-motion` 或页面隐藏时跳过；
- 光路颜色跟随泳道色；不使用大面积模糊，不会持续跑帧循环（只在事件到达时短暂渲染）。

### 泳道列收敛（2026-10 修正 2）

- 主列只保留研究环节：**宏观 / 行业 / 个股**；
- **交易列**：只有该 case 真正出现交易活动（`trade/plan.md` 或 trader 事件）时才显示，否则隐藏；
- **Lead 列**：工作流模式下隐藏，改为顶部状态条「汇编 / 签发：状态 · 终稿 vN · 查看终稿」；交付物模式保留 Lead 列（终稿本身是交付物）；
- **轮次折叠**：一次 `agent.run.started → finished/failed` 收成一张「第 N 轮 · X 步 · 时长（含 Y 个交付物）」卡片，点开展开；替代之前的「过程 N 步」折叠；
- 状态条里「查看终稿」可直接打开 `final_report.md`。

### 模型可视化（对齐 Lancer 的「复数模型 → 节点」飞线）

- 每个主环节列头显示该员工当前模型（`模型 deepseek-v4.1-flash`）；配置与实际不一致时变红并标 ↑，tooltip 显示配置/实际；
- 工作流卡片新增模型事件：`启动会话 · <model>`、`实际模型 · <model>`、`模型 → <agent> · <model>`；卡片描边用模型色（按模型名哈希取色）；
- 状态条汇总：`模型：deepseek-v4.1-flash · 切换 N 次`（来自 `S.models` 配置 + 账本 `model.changed` 计数）；
- 飞线：`agent.run.started` / `model.changed` / `agent.model_actual` 事件到达时，光路从**该员工列的模型标签**飞向新卡片，颜色跟随模型；其余事件仍从中栏账本流水飞向卡片；
- 图例新增「模型调用」。

运行时边界：员工当前是一轮一个模型（profile patch 决定）；「同一员工同一轮内多模型路由」需要改 `runtime/agents/employee.js` 与 `scripts/pipeline.js`（按步骤切模型并逐次上报 `agent.model_actual`）。面板侧已能展示多模型与切换。

### 字体与栏宽自适应（参考 Lancer）

- 字体栈：`--font-ui: ui-sans-serif, -apple-system, BlinkMacSystemFont, "SF Pro Text", "PingFang SC", "Segoe UI", sans-serif`；等宽 `--font-mono: ui-monospace, "SF Mono", Menlo, Consolas`；
- 字阶：`--fs-2xs 10 / --fs-xs 11 / --fs-sm 12 / --fs-base 13 / --fs-md 15`，全局 `line-height:1.5`、`letter-spacing:-.005em`、`-webkit-font-smoothing:antialiased`；
- 按钮/列表/账本流水/门禁/知识库说明统一到 11–13px；泳道 SVG 内：列名 11px、状态 7.8px、模型 7.4px、卡片标题 9.2px、卡片元信息 7.4px；
- 左栏默认 300px（clamp 260–420，可拖拽），右栏默认 660px（clamp 360–920）；
- 泳道列宽按内容自适应：取该列最长标签宽度，夹在 128–260px；总宽再按容器宽度自动缩放（「适应」按钮）；
- 左栏员工行改为两行布局：第一行姓名，第二行状态/技能/知识库/交付状态，长文本省略而不是挤掉姓名；表格 `word-break` 自动换行。

### 聚焦模式 / 模型调用行 / 顶部视角 tab（2026-10 追加）

- 聚焦：点「全部 / 宏观 / 行业 / 个股」后，非聚焦泳道 `opacity:.12 + grayscale(1)`，聚焦列保留底色与蓝色描边，跨列边也只画聚焦列的；点「全部」或再点一次取消；
- 中栏顶部「模型调用」：**每行 = 一轮工作流**，列：状态点 / 员工 / 模型 / 状态（运行中·完成·失败 + 耗时）/ 步数·环节 / 本轮 token / 开始时间；最多 6 行，超出滚动；点行聚焦对应泳道；每行一条模型色虚线飞线连到该泳道最新触发节点；
- 顶部视角 tab：**总览 / 工作流 / 交付物 / 设置**；工作流转泳道工作流模式，交付物切交付物模式并滚到交付物区，设置打开「模型 / 技能 / 环境自检 / 计划审批策略」弹窗；状态写入 URL `?view=`；
- 环境自检弹窗内可点「重新检查」，模型/技能按钮复用原有配置弹窗。

### 面向普通用户的简化（2026-10 追加）

- 左栏只保留：**团队**（员工 → 点击展开任务列表，每条任务显示处理模型/时间，可点「改」配置模型）、**Token 消耗**；上传/计划/复核/交付物/历史收进「显示更多」；
- 中栏改为「工作动态」：默认隐藏读文件、锁、心跳、图表批量生成等噪声；同一文件只保留最新版本，同一门禁只保留最新结论；
- 中栏每类事件有中文小图标与颜色：派/跑/完/写/过/停/缺/答/审/结/模/传/库；模型调用行带员工头像与状态色；
- 右栏移除「共享文件 · 锁队列」，泳道图占满整列，图例压缩为 4 项；
- 术语去技术化：账本流水 → 工作动态，任务线 → 团队，锁队列默认不展示（数据仍在，可在「显示更多」/账本里查）。

### 未答复任务：对话框上方的隐藏列表（2026-10 追加）

- 位置：中栏输入框上方一条折叠行「待回复 N 条 · 未答复 ▸」；默认收起，不占空间；
- 数据：当前 case 下所有 `status !== done` 的任务（派活后未交付的），按创建时间倒序；
- 点标题展开列表：每条显示员工头像、任务名（可自定义）、时间；点某条直接切到该员工对话；
- 任务交付（`task.delivered`）后自动从列表消失，计数同步；
- 任务名来自 `task.name`（任务配置表可改），未改名时回退到原始指令摘要。

### 混合规划模式 + 待办详情（2026-10 追加）

- `config/desk.json` 新增 `planning.mode`：宏观/行业/个股 = `guided`（固定骨架 + 规划器补充），审计/法律/交易 = `fixed`（固定模板、不调规划模型）；
- `config/tasks/<agent>.json`：每个员工的固定子任务模板（名称/顺序/依赖/档位/默认模型），由 `planner.js --save-template` 生成；
- 任务配置表每个员工多两个按钮：**设为默认模板**（把当前计划钉成该员工默认）、**恢复内置**（删除自定义模板）；
- 固定任务可单独改模型：`plan.steps[].model` 优先于档位路由，`run-plan` 按任务模型执行；
- 待回复/待批列表点击 → 中栏出现完整详情卡：计划目标、全部任务名称 + 完整任务文本 + 分配模型 + 执行状态（随 `agent.step.*` 更新），可直接批准执行/退回；任务则显示完整原始指令。
