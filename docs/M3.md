## 1. 先修：panel 打不开的三个真问题

| 问题 | 现象 | 修法 |
|---|---|---|
| --root 默认取 process.cwd() | 从别的目录启动 → 面板 404、vault 写到错误位置 | 默认按 broker.js 位置推出项目根，--root 仍可覆盖 |
| 没有 /live 入口 | 只能手拼 /?live=1&case=...，容易漏参数 | /live → 302 到正确 URL；启动时打印两个入口 |
| file:// 打开时没有 API 基址 | 双击 html 后 ?live=1 的 fetch 打到 file:// | 检测 location.protocol：file 下用 http://127.0.0.1:7801 |

现在只有一种记法：

    node runtime/server/broker.js
    # 实时看板  http://127.0.0.1:7801/live?case=case-2026-001
    # 剧本原型  http://127.0.0.1:7801/?proto=1

由 broker 托管时**默认就是 live**（?proto=1 才回到剧本），不用再记参数。

### 一条命令起服务（新增）

    ./scripts/dev                       # 起 broker + 打印两个入口 + 自动开浏览器
    ./scripts/dev --no-open --port 7810 # 不弹浏览器 / 换端口
    ./scripts/dev --case case-2026-002  # 指定默认 case

端口被占用会自动 +1 试到 7810，并把实际 URL 打出来。

### 另外修掉的两个「重启才暴露」的问题

1. **重启后账本流水只剩 1 条** —— 重放只恢复了文件版本和门禁，没把历史事件装回内存缓冲，`/api/events?since=0` 返回空。已在 replay 里回填。
2. **泳道图每重启一次多一个「立项」节点** —— `broker.started` 被当成图节点，历史里攒了三个。已从图节点里移除，只留在流水里。
3. **时间轴被空闲时间拉长** —— 隔了 10 分钟再打开，横轴变成 0~656s，节点全挤在左边。改成只看最近 5 分钟；空闲超过窗口时把「现在」冻结在最后一条事件。

## 2. M3-1：派活与审批走 Broker

| 接口 | 作用 |
|---|---|
| POST /api/task | 派活：{case, agent, text, target?} → 写 task.assigned 进账本 |
| GET /api/tasks?case= | 某个 case 的任务列表 |
| POST /api/capability | 员工申请能力：{case, agent, skill, reason} → capability.requested |
| GET /api/capabilities?case= | 待审批/已决列表 |
| POST /api/capability/decide | {case, id, approve} → capability.approved/denied，重复审批返回 409 |

面板侧：
- live 下选中员工后输入框可用，回车 → POST /api/task，账本立刻出现「你 派活 → industry：…」；
- 待审批条目**固定在输入框上方**（不再被流水淹没），批准/拒绝直接调接口。

## 2.5 模型配置也从只读变成可配（补漏）

之前 live 模式下左下角模型栏写着「由 mission 托管」，纯只读——因为 Broker 当时没有模型接口。补上：

| 接口 | 作用 |
|---|---|
| GET /api/models?case= | 默认模型 + 员工覆盖 + 目录 |
| POST /api/model | {case, agent\|null, provider, model} → model.changed |
| POST /api/models/catalog | 新增模型（key_ref 只收 env:/keychain:，明文拒绝） |
| DELETE /api/models/catalog/:id | 删自建模型（内置不可删） |

**配置写进账本并可从账本重放**——重启 Broker 后 stock→v4.1、audit→acme 都还在。实测：

    set industry → acme/reason-1
    restart broker
    after restart byAgent {"stock":{...v4.1},"audit":{...reason-1},"industry":{...reason-1}}

顺手修掉一个 redirect bug：`/live` 只保留 case，把 `sel`/`model` 等参数吞掉了。现在原样保留整个 query。

## 2.6 技能库也接上了（补漏）

和模型一样，live 模式下技能抽屉原本是空的——Broker 没有技能接口。补上：

| 接口 | 作用 |
|---|---|
| GET /api/skills?case= | 目录 + 每员工装配 + 已加载记录 |
| POST /api/skill/install | {case, id, installed} → skill.installed / uninstalled（卸载会级联撤销装配） |
| POST /api/skill/assign | {case, agent, id, on} → skill.granted / revoked（未安装的技能拒绝装配） |
| POST /api/skills/catalog | 新增自建技能/插件（plugin 的 key_ref 只收 env:/keychain:） |

**能力审批现在会真的生效**：`POST /api/capability/decide` 批准时，Broker 自动执行安装 + 装配，并补发 `skill.installed` / `skill.granted`（带 `via: "capability"` 便于追溯）。实测：

    capability.requested trader peer-scraper
    skill.granted         trader peer-scraper
    capability.approved   trader peer-scraper

技能变更和模型一样走**账本重放**：重启 Broker 后装配关系不丢。

## 3. M3-3：事件自带 lane / parents

以前血缘是面板自己猜的（同车道上一个节点）。现在 Broker 在 emit 时就算好：

    { seq: 7, type: 'file.written', actor: 'industry',
      lane: 'industry', parents: [3], path: 'research/industry.md', v: 1 }

- lane：actor 是员工就用员工，否则归到 lead；task.assigned 归到被派的员工；
- parents：同车道上一个**图节点**（lock.granted/released 这类噪声事件不占位）；
- 重放账本时同步重建 lane/parents，重启不丢血缘。

面板优先使用 Broker 给的 parents，拿不到才回退到自己推。
