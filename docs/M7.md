# M7：员工的个人知识库（LLM Wiki）

目标：员工在工作中学到的事实、口径、结论和来源，各自存进自己的 Wiki 库，下次开工自动带进上下文。

## 存储结构

```
runtime/kb/<agent>/
  index.json          # 页面索引：slug / title / tags / sources / links / updated / snippet
  <slug>.md           # 一页 = markdown + frontmatter(title, agent, tags, sources, links, created, updated)
```

- 库是**按员工隔离**的（macro 的库只有 macro 和装配给他的服务能查）；
- 页面带 `tags`、`sources`、`links`，是 Wiki 而不是平铺笔记：可以按标签检索、按 links 建关系；
- 写入是 append-or-update（同 slug 更新，保留 created），不改历史（后续可加页面版本）。

## 接口 / 命令

| 动作 | HTTP | CLI |
|---|---|---|
| 存一页 | `POST /api/kb/put` | `desk kb --put --title .. --file .. --tags a,b --source ..` |
| 列页面 | `GET /api/kb/list?agent=` | `desk kb --list` |
| 检索 | `GET /api/kb/search?agent=&q=` | `desk kb --search --q ".."` |
| 读一页 | `GET /api/kb/page?agent=&slug=` | `desk kb --get --slug ..` |
| 各员工页数 | `GET /api/kb/counts` | — |

每次写入记 `kb.page.saved` 事件（面板账本可见）。

## 与运行时/面板的衔接

- `runtime/agents/employee.js` 启动时拉该员工最近 8 页（标题 + 摘要）注入提示词「你的知识库」，并带 `desk kb --get --slug` 用法；
- 提示词固定段落要求「每轮把可复用事实/口径存进库，带 tags 和来源，不写没验证的猜测」；
- 面板左栏每个员工显示 `库·N`（自己的页面数），悬停有说明；账本显示「存进自己的知识库：标题（#标签）」。

## 实测

- 宏观员工写入「白酒行业量价口径」（tags 行业/口径，source 渠道调研），`kb --search --q 口径` 命中，`counts` 显示 macro=1；
- 提示词注入已接入（下一轮员工启动即带库）；面板 `库·N` 已显示。

## 还没做

1. 页面版本与 diff（现在同 slug 覆盖，历史要靠账本事件）；
2. 跨员工共享/引用（现在库是私有的，同事只能通过装配技能或复核间接用）；
3. 向量/语义检索（现在是标题 + tags + 摘要的关键字匹配）；
4. 面板内的库浏览与编辑（现在只能 CLI 或预览 md 文件）。
