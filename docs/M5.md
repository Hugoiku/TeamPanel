# M5：员工独立运行时（每员工一个 DSH 会话 + 独立模型）

## 1. 为什么要改

M1–M4 的员工是 DSH Team 的 teammate（spawn_teammate 起）。这条路有一个硬限制：
同一个 Team 里的员工共用会话模型，面板左下角给某个员工换模型只改元数据，改不了他真正在跑的模型。
用户明确要求「panel 的模型应该是独立运行的，用的是 opencode-go 的模型配置」，所以换运行时。

## 2. 方案：一名员工 = 一个独立的 dsh headless 会话

```
panel / broker  --POST /api/agent/run-->  runtime/agents/employee.js
                                               |  读 Broker 里该员工的模型配置
                                               |  生成 runtime/profiles/<agent>.yml（provider + model）
                                               v
                     dsh --profile headless --patch runtime/profiles/<agent>.yml "<任务书>"
                                               |  自己的 DSH_HOME、自己的会话、自己的模型
                                               v
                     ./scripts/desk acquire/write/gate/task  -->  Broker（锁、版本、账本、门禁）
```

要点：

1. **模型独立**：每人一份 profile patch，`agent-default-model` 指向 opencode-go + 该员工配置的模型；
   provider 凭据走 `apiKeyEnv: OPENCODE_GO_API_KEY`（从 ~/.dsh 的 credentials refs 读，不落盘）。
2. **仍是 DSH 架构**：跑的就是 dsh CLI 本体（headless profile），有自己的会话、上下文、工具循环、会话账本。
3. **共享文件仍排队**：所有 vault 读写只能走 desk → Broker 的锁队列/版本 CAS，与 M1 设计一致。
4. **实际模型可核对**：员工进程结束时用 `desk model` 回报实际模型，面板显示「配置 vs 实际」。

## 3. 已验证

- `dsh --profile headless --patch runtime/profiles/macro.yml "只输出 OK"` → `OK`（opencode-go/deepseek-v4.1-flash）；
- 宏观员工独立跑完一轮：`research/macro.md v1` + `research/macro.json v1`，两条 G-DATA，账本有锁事件；
- 每员工 DSH_HOME 隔离在 `runtime/dsh-home/<case>/<agent>/`（per-case session），日志落 `runtime/agent-runs/<agent>-<ts>.log`。

## 4. 新增文件

| 文件 | 作用 |
|---|---|
| `runtime/agents/employee.js` | 启动一名员工：读模型配置 → 生成 patch → 跑 dsh headless → 回报实际模型与 run 事件 |
| `runtime/profiles/<agent>.yml` | 该员工的 DSH profile patch（provider/model 在这里定） |
| `scripts/pipeline.js` | 按 DAG 跑 6 名员工（宏观/行业 → 个股 → 审计+法律 → 交易） |
| Broker `POST /api/agent/run` | 面板派活后直接起该员工的独立会话（409 防重入） |
| Broker `POST /api/event` | 员工进程上报 agent.run.started / finished / failed |

## 5. 与 M1–M4 的差别

| | M1–M4（DSH Team teammate） | M5（独立会话） |
|---|---|---|
| 模型 | 全队共用会话模型 | 每员工独立，面板可配 |
| 上下文 | 共享 Lead 的 Team 上下文 | 各自独立会话 |
| 启动 | spawn_teammate | `dsh --profile headless --patch ...` |
| 观测 | 账本事件 | 账本事件 + agent.run.* 生命周期 |
| 权限 | Team 工具 | shell + desk（vault 仍只走 desk） |

## 7. 实测限制：opencode-go 目前只有 deepseek-v4.1-flash 能起

用 dsh headless 逐个试模型：

| 模型 | 结果 |
|---|---|
| opencode-go/deepseek-v4.1-flash | ✓ 正常出结果 |
| opencode-go/deepseek-v4.1 | ✗ UNKNOWN_MODEL（provider 没配这个模型） |
| opencode-go/deepseek-v3.2 | ✗ UNKNOWN_MODEL |
| deepseek-official/deepseek-flash | ✗ MISSING_CREDENTIAL（需要 DEEPSEEK_API_KEY，桌面端的账号授权没有暴露给 CLI） |

所以「每员工独立模型」现在能做的是：**每人一份独立配置 + 独立会话**，但可选模型只有 flash；
Broker 目录里已加 `verified` 标记，未接入的模型面板会显示「未接入」，选中会提示启动失败，
employee.js 启动前也会拦掉（退出码 6），不会白跑一轮。等 opencode-go 接入更多模型，改配置就能真正异构。
